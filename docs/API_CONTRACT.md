# CCMS API Contract Specification (v1)

**API Version**: `v1`  
**Base URL**: `http://localhost:8000/api/v1`  
**OpenAPI Specification**: `http://localhost:8000/openapi.json`  
**Specification Standard**: RESTful JSON, ISO 8601 UTC Timestamps  

---

## 1. Conventions & Standards

- **Timestamps**: All timestamps are formatted as ISO 8601 UTC strings (`YYYY-MM-DDTHH:MM:SSZ`).
- **Authentication**: HTTP Bearer JWT tokens sent via standard header: `Authorization: Bearer <token>`. Minimized token claims include `sub`, `iat`, `exp`, and `role`. Authoritative profile state is loaded from the database.
- **Content-Type**: `application/json` for all request and response payloads.
- **Pagination**: `GET /api/v1/complaints/mine` supports `limit` (default 50, maximum 100) and `offset` (default 0) query parameters. Returns a plain JSON array ordered descending by submission time (`created_at DESC, id DESC`).
- **Roles**: `student`, `staff`, `admin`.
- **Rate Limiting**: In-process sliding-window rate limiting on `/api/v1/auth/login` and `/api/v1/auth/register`. Exceeding limits returns `429 Too Many Requests` with a `Retry-After` header.

## 3. Endpoint Specifications

### 3.1 `POST /api/v1/auth/register`
Creates a new student account. Registration is strictly constrained to the `student` role. Password-registered accounts are created with `email_verified=false`.

**Request Schema:**
```typescript
interface RegisterRequest {
  name: string;      // 2–100 characters, whitespace trimmed
  email: string;     // Valid email address (must be unique)
  password: string;  // 8–100 characters
}
```

**Response Schema (`201 Created`):**
```typescript
interface UserSafeResponse {
  id: number;
  name: string;
  email: string;
  role: "student" | "staff" | "admin";
  is_active: boolean;
  department_id: number | null;
  created_at: string; // ISO 8601 UTC
  email_verified: boolean;
  email_verified_at: string | null; // ISO 8601 UTC or null
}
```

**Errors:**
- `409 Conflict`: Email already exists.
- `422 Unprocessable Content`: Validation failed (e.g. password < 8 chars or extra injected fields).

---

### 3.2 `POST /api/v1/auth/login`
Authenticates credentials and issues a signed JWT Bearer access token.

**Request Schema:**
```typescript
interface LoginRequest {
  email: string;     // Registered email
  password: string;  // Account password
}
```

**Response Schema (`200 OK`):**
```typescript
interface TokenResponse {
  access_token: string;
  token_type: "bearer";
  expires_in: number; // Seconds (e.g. 86400)
  user: UserSafeResponse;
}
```

**Errors:**
- `401 Unauthorized`: Bad credentials (generic response to avoid account enumeration).
- `403 Forbidden`: Account is inactive.

---

### 3.3 `POST /api/v1/auth/google/start`
Initiates the Google OpenID Connect Authorization Code flow with PKCE S256 and client-bound transaction state.

**Headers:**
- `Origin: <frontend-origin>` (Must match configured `CORS_ORIGINS`)

**Request Schema:**
```typescript
interface GoogleAuthStartRequest {
  client_challenge: string; // 10–128 chars base64url SHA-256 challenge generated by frontend
}
```

**Response Schema (`200 OK`):**
```typescript
interface GoogleAuthStartResponse {
  authorization_url: string; // Google OAuth authorization URL to open in popup window
  state: string;             // Opaque random state identifier
}
```

**Errors:**
- `403 Forbidden`: Request Origin is not allowed.
- `422 Unprocessable Content`: Invalid challenge format.
- `503 Service Unavailable`: Google Sign-In is disabled on the server.

---

### 3.4 `GET /api/v1/auth/google/callback`
Receives the authorization code and state parameter from Google, validates and atomically consumes the state, exchanges the authorization code using PKCE, verifies the Google ID token and claims, resolves or creates the internal student user, creates a short-lived single-use handoff ticket, and returns a hardened minimal HTML page that dispatches the ticket to `window.opener` via `postMessage`.

**Query Parameters:**
- `code`: Google authorization code.
- `state`: OAuth state token.
- `error`: Optional provider error string.

**Response (`200 OK HTML`):**
- Minimal HTML document with strict Content-Security-Policy (`default-src 'none'; script-src 'nonce-...'; style-src 'unsafe-inline';`), `Referrer-Policy: no-referrer`, and `Cache-Control: no-store`.
- Automatically posts message to `window.opener.postMessage(payload, targetOrigin)` and closes itself.
- Payload structure:
```typescript
interface GoogleAuthSuccessPayload {
  type: "CCMS_GOOGLE_AUTH_SUCCESS";
  ticket: string; // Single-use handoff ticket
  error: null;
  link_required: false;
}

interface GoogleAuthErrorPayload {
  type: "CCMS_GOOGLE_AUTH_ERROR";
  ticket: null;
  error: string; // User-facing safe error message
  link_required: boolean; // True if account already exists with password
}
```

---

### 3.5 `POST /api/v1/auth/google/exchange`
Redeems the single-use handoff ticket by submitting the matching client verifier proof. Atomically invalidates the ticket, validates the origin, and issues the standard CCMS `TokenResponse`.

**Headers:**
- `Origin: <frontend-origin>` (Must match origin recorded at `/auth/google/start`)

**Request Schema:**
```typescript
interface GoogleExchangeRequest {
  ticket: string;          // Single-use handoff ticket from postMessage
  client_verifier: string; // Matching client verifier (proves possession of original client_challenge)
}
```

**Response Schema (`200 OK`):**
```typescript
interface TokenResponse {
  access_token: string;
  token_type: "bearer";
  expires_in: number;
  user: UserSafeResponse;
}
```

**Errors:**
- `400 Bad Request`: Invalid verifier proof, ticket expired, or ticket already consumed.
- `403 Forbidden`: Origin mismatch or user account is inactive.
- `503 Service Unavailable`: Google authentication is disabled.

### 3.5 `POST /api/v1/departments/suggest`
Automated keyword-based advisory department suggestion. Evaluates complaint title/description drafts against provisional campus department keyword heuristics and returns ranked recommendations.

> [!NOTE]
> This service is a deterministic **keyword-based advisory heuristic** with no vector database or external model. All suggestions are strictly advisory; students always retain final authoritative choice when submitting a complaint. Internal suggestion failures never block complaint creation.

**Headers:**
```http
Authorization: Bearer <access_token> // Must have role 'student'
```

**Request Schema:**
```typescript
interface DepartmentSuggestionRequest {
  title: string;       // 3–120 characters
  description: string; // 10–2000 characters
}
```

**Response Schema (`200 OK`):**
```typescript
interface DepartmentSuggestionResponse {
  status: "provisional_advisory" | "uncertain" | "error_fallback";
  version: string;
  suggestions: Array<{
    department_id: number;
    department_name: string;
    confidence_score: number; // 0.0 to 1.0 (e.g. 0.70, 0.80)
    rationale: string | null;  // Sorted deterministic list of matched keywords
  }>;
  disclaimer: string;
}
```

**Status Semantics for Frontend Handling:**
- `status === "provisional_advisory"`: Clear highest-confidence department winner identified. `suggestions` contains ranked recommendations.
- `status === "uncertain"`: The heuristic cannot confidently identify one clear winner.
  - If candidates are tied or near-tied: `suggestions` contains the tied candidate options for the student to consider.
  - If no keywords match: `suggestions` is empty `[]`.
- `status === "error_fallback"`: An internal failure occurred while evaluating heuristics. `suggestions` is `[]`.

*Frontend Rule:* Use `status` to render appropriate confidence/uncertainty badges. Use `suggestions.length > 0` to determine whether candidate suggestions are available to display.

**Errors:**
- `401 Unauthorized`: Missing or invalid Bearer token.
- `403 Forbidden`: Authenticated user is not a student (staff/admin rejected).

### 3.6 `POST /api/v1/complaints`
Lodges a new complaint against an active department. Creates a server-side record with initial status `submitted`.

**Headers:**
```http
Authorization: Bearer <access_token> // Must have role 'student'
```

**Request Schema:**
```typescript
interface ComplaintCreate {
  title: string;          // 3–120 characters, non-whitespace
  description: string;    // 10–2000 characters, non-whitespace
  department_id: number;  // Positive integer referencing active department
}
```

**Response Schema (`201 Created`):**
```typescript
interface ComplaintResponse {
  id: number;
  title: string;
  description: string;
  department_id: number;
  department_name: string;
  created_by_id: number;
  status: "submitted";
  created_at: string; // ISO 8601
}
```

**Errors:**
- `400 Bad Request`: Department is inactive.
- `403 Forbidden`: Authenticated user is not a student.
- `404 Not Found`: Department ID does not exist.
- `422 Unprocessable Content`: Validation error on title/description length or blank string.

---

### 3.7 `GET /api/v1/complaints/mine`
Returns the personal complaint history of the authenticated student, sorted newest first (`created_at DESC, id DESC`).

**Headers:**
```http
Authorization: Bearer <access_token> // Must have role 'student'
```

**Query Parameters:**
- `limit` (integer, optional): Maximum number of records to return. Default: `50`, Maximum: `100`.
- `offset` (integer, optional): Number of records to skip for pagination. Default: `0`.

**Response Schema (`200 OK`):**
Returns a plain JSON array of complaints:
```typescript
type ComplaintHistoryResponse = Array<{
  id: number;
  title: string;
  department_name: string;
  status: "submitted";
  created_at: string; // ISO 8601
}>;
```

## 4. Structured Error Responses

### 4.1 Standard Error Format (`400`, `401`, `403`, `404`, `409`, `500`)
```json
{
  "detail": "Descriptive message"
}
```

### 4.2 Validation Error Format (`422`)
```json
{
  "detail": [
    {
      "field": "body -> title",
      "message": "Title must contain at least 3 non-whitespace characters",
      "type": "value_error"
    }
  ]
}
```

### 4.3 Rate Limit Error Format (`429`)
Returned by `/api/v1/auth/login` and `/api/v1/auth/register` when request rate exceeds the sliding-window threshold.
```json
{
  "detail": "Rate limit exceeded. Try again in 60 seconds."
}
```
**Response Headers:**
- `Retry-After`: integer number of seconds the client should wait before retrying.
